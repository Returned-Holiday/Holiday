# 백엔드(Python·Django) 시큐어코딩 규칙

진단가이드 구현 단계 49개 약점을 Django 기준 규칙으로 옮겼다. CI의 Semgrep·Bandit이 대부분을 자동으로 잡지만, **권한·로직 항목은 도구가 못 잡으니 리뷰에서 본다.**

## 바로 외울 금지 목록

| 금지 | 대신 | 약점 |
|---|---|---|
| `raw()`, `extra()`, `cursor.execute(f"...")`, 문자열로 만든 SQL | ORM, 꼭 필요하면 파라미터 바인딩 | SQL 삽입 |
| `eval`, `exec`, `compile`, `__import__`(외부 입력) | 허용 목록 딕셔너리로 선택 | 코드 삽입 |
| `os.system`, `subprocess(..., shell=True)` | 사용하지 않음 | OS 명령어 삽입 |
| `pickle`, `marshal`, `shelve`, `yaml.load`(Loader 미지정) | `json`, `yaml.safe_load` | 역직렬화 |
| `xml.etree`, `lxml`로 외부 XML 파싱 | 사용하지 않음(필요하면 `defusedxml`) | XXE |
| `random` 모듈(보안 용도) | `secrets` | 적절하지 않은 난수 |
| `hashlib.md5`, `hashlib.sha1` (용도 무관) | `hashlib.sha256` 이상, 비밀번호는 Django 해셔 | 취약한 암호 알고리즘 |
| `requests(..., verify=False)` | 기본값 유지 | 인증서 검증 |
| `except Exception:`, `except:`, `except ...: pass` | 구체적 예외만 처리, 처리할 게 없으면 잡지 않음 | 부적절한 예외 처리, 오류 상황 대응 부재 |
| `print`, `pdb`, `breakpoint()`, 디버그 툴바 | `logging` | 남은 디버그 코드 |
| 예외 메시지·`str(e)`·serializer 내부 에러를 응답에 그대로 | 공통 예외 핸들러의 일반 메시지 | 오류 메시지 정보노출 |
| `AllowAny`(공개 API 외) | 기본값(`IsAuthenticated`) | 인증 없는 중요 기능 |
| `Model.objects.get(pk=...)`로 사용자 데이터 조회 | `request.user`로 거른 queryset | 부적절한 인가(IDOR) |
| `tempfile.mktemp`, 업로드 파일 디스크 저장 | 메모리 처리(`docs/security.md` 3-5) | 파일 업로드, TOCTOU |
| `assert`로 보안 검사 | `if` + 예외 | 취약한 API(최적화 시 assert 제거됨) |
| settings에 비밀값 기본값 | 환경변수·Secrets Manager, 없으면 시작 실패 | 하드코드된 중요정보 |
| 로그에 이메일·전화번호·비밀번호·OCR 원문 | 마스킹 필터, 비밀번호·OCR 원문은 아예 기록 안 함 | 중요정보 노출 |

## 49개 항목별 규칙

### 입력데이터 검증 및 표현 (17)
| # | 약점 | 규칙 |
|---|---|---|
| 1 | SQL 삽입 | ORM만. 설정 파일 값도 외부 입력으로 본다 |
| 2 | 코드 삽입 | `eval`·`exec` 금지. 사용자 입력을 Django `Template()`으로 컴파일하지 않음 |
| 3 | 경로 조작·자원 삽입 | 사용자 입력으로 파일 경로·포트·호스트를 만들지 않음 |
| 4 | XSS | API는 JSON만 반환. 템플릿을 쓰는 곳(에러 페이지 등)의 자동 이스케이프를 끄지 않음(`mark_safe`, `|safe` 금지) |
| 5 | OS 명령어 삽입 | OS 명령 실행 없음 |
| 6 | 위험한 형식 파일 업로드 | 확장자 + 시그니처 + 크기 + 메모리 처리 |
| 7 | 신뢰되지 않는 URL 자동접속 | 서버 리다이렉트에 사용자 입력 URL 금지. 불가피하면 `url_has_allowed_host_and_scheme` |
| 8 | XXE | XML 미사용 |
| 9 | XML 삽입 | XML 미사용 |
| 10 | LDAP 삽입 | LDAP 미사용 |
| 11 | CSRF | Django CSRF 미들웨어 유지. `@csrf_exempt` 금지 |
| 12 | SSRF | 사용자 입력 URL로 서버가 요청하지 않음. 외부 호출 주소(OCR)는 설정에 고정 |
| 13 | HTTP 응답분할 | 헤더·쿠키 값에 사용자 입력을 넣지 않음 |
| 14 | 정수형 오버플로 | 숫자 입력은 serializer에서 범위 지정(`min_value`, `max_value`) |
| 15 | 보안기능 결정에 사용되는 부적절한 입력값 | 역할·소유자·우선순위·상태는 서버 값으로만 판단. 요청 body의 `user_id`, `is_staff` 같은 값 무시 |
| 16 | 메모리 버퍼 오버플로 | 해당 없음(Python) |
| 17 | 포맷 스트링 삽입 | 사용자 입력을 `str.format`·`%`의 **형식 문자열**로 쓰지 않음. 로그는 `logger.info("... %s", value)` |

### 보안기능 (16)
| # | 약점 | 규칙 |
|---|---|---|
| 1 | 적절한 인증 없는 중요기능 허용 | 기본 거부. 비밀번호 변경·탈퇴는 현재 비밀번호를 함께 받아 확인 |
| 2 | 부적절한 인가 | 모든 뷰에 권한 클래스 명시, 사용자 데이터는 `request.user` 필터, 공개 데이터는 공개 매니저 |
| 3 | 중요한 자원에 대한 잘못된 권한 설정 | 설정·비밀 파일 600/640, 프로세스는 root가 아닌 계정 |
| 4 | 취약한 암호화 알고리즘 | MD5·SHA1·DES 금지 |
| 5 | 암호화되지 않은 중요정보 | 비밀번호는 해시만, 전송은 TLS, 쿠키 `Secure` |
| 6 | 하드코드된 중요정보 | 코드·테스트·주석에 비밀값 없음. 해시 형태도 금지, 고정 솔트 금지 |
| 7 | 충분하지 않은 키 길이 | 대칭 128비트 이상, RSA 2048 이상 (직접 암호화하지 않는 것이 원칙) |
| 8 | 적절하지 않은 난수 | `secrets` 사용 |
| 9 | 취약한 비밀번호 허용 | KISA 규칙 검증기를 가입·변경 모두에 적용 |
| 10 | 부적절한 전자서명 확인 | 해당 없음 |
| 11 | 부적절한 인증서 유효성 검증 | `verify=False` 금지 |
| 12 | 하드디스크에 저장되는 쿠키 | 세션 쿠키에 민감정보 없음, 유효기간 15분 |
| 13 | 주석문 안에 포함된 시스템 주요정보 | 주석에 계정·키·내부 주소 금지 |
| 14 | 솔트 없이 일방향 해시 | 비밀번호는 Django 해셔(솔트 포함)만 |
| 15 | 무결성 검사 없는 코드 다운로드 | 의존성 해시 고정 설치 |
| 16 | 반복된 인증시도 제한 기능 부재 | django-axes 5회 30분 + 요청 제한 |

### 시간 및 상태 (2)
| # | 약점 | 규칙 |
|---|---|---|
| 1 | TOCTOU | "확인 후 사용" 대신 원자적 처리: `get_or_create`, `update_or_create`, 유일 제약, `transaction.atomic`, 필요 시 `select_for_update` |
| 2 | 종료되지 않는 반복문·재귀 | 재귀 금지, 반복은 상한을 둔다. 목록 크기 상한(페이지 50) |

### 에러처리 (3)
| # | 약점 | 규칙 |
|---|---|---|
| 1 | 오류 메시지 정보노출 | 공통 예외 핸들러, `DEBUG=False`, 404·500 핸들러 |
| 2 | 오류 상황 대응 부재 | 빈 `except`·`pass` 금지 |
| 3 | 부적절한 예외 처리 | `except Exception` 금지. 예상 가능한 예외만 구체적으로 |

### 코드오류 (5)
| # | 약점 | 규칙 |
|---|---|---|
| 1 | Null Pointer 역참조 | `None` 가능 값은 확인 후 사용, `.first()` 결과 확인, `get_object_or_404` |
| 2 | 부적절한 자원 해제 | 파일·연결·이미지는 `with` 문 |
| 3 | 해제된 자원 사용 | `with` 블록 밖에서 자원 사용 금지 |
| 4 | 초기화되지 않은 변수 사용 | 모든 분기에서 변수 정의 |
| 5 | 신뢰할 수 없는 데이터의 역직렬화 | `pickle` 등 금지, JSON만. Django 세션 직렬화는 JSON(기본값) 유지 |

### 캡슐화 (4)
| # | 약점 | 규칙 |
|---|---|---|
| 1 | 잘못된 세션에 의한 데이터 정보 노출 | 뷰 클래스 속성·모듈 전역 변수에 요청별 데이터 저장 금지 |
| 2 | 제거되지 않고 남은 디버그 코드 | `print`, 디버그 툴바, 테스트용 엔드포인트, 주석 처리된 코드 금지 |

| 4 | Private 배열에 Public 데이터 할당 | 외부에서 받은 리스트를 그대로 내부 상태로 저장하지 않고 복사 |

### API 오용 (2)

## 리뷰에서 반드시 보는 것 (도구가 못 잡음)
- [ ] 새 뷰에 권한 클래스가 명시되어 있는가
- [ ] 사용자 데이터 queryset이 `request.user`로 걸러지는가
- [ ] 사고·조치 조회가 공개 매니저를 쓰는가
- [ ] 설문 선택 항목·완료 처리의 교차 검증이 있는가
- [ ] 응답에 불필요한 필드(내부 ID, 다른 사용자 정보, 이메일)가 없는가
- [ ] 에러 응답이 공통 형식인가
- [ ] 보안 이벤트를 로그로 남기고, 로그에 개인정보가 없는가
