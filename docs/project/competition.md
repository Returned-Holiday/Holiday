## 2라운드 심사 기준

| 부문 | 비율 | 평가 내용 |
|---|---|---|
| 개발 | 60% | 창의성, 적용성, 완성도 등 |
| 보안 | 40% | 제거되지 않은 보안위협의 수(시스템에서 발생할 수 있는 보안위협의 수를 분석해 보안성 수준 검토) |

보안 부문 평가 기준(사전교육 자료 26쪽):
1. **1순위**: 빌드라인당 소스코드 보안약점의 수
2. **2순위**: 보안약점 조치율
3. **3순위**: 보안약점을 줄이기 위한 구조적 설계 — **개발기획서 "2. 주요 기능 및 개발환경"에 구조적 설계나 구현 방법을 기술**해야 한다

동점이면 실현가능성 > 영향력 > 창의성 순.

## 진단 기준: 구현 단계 보안약점 49개

| 분류 | 개수 | 예 |
|---|---|---|
| 입력데이터 검증 및 표현 | 17 | SQL 삽입, XSS, CSRF, SSRF, 파일 업로드 |
| 보안기능 | 16 | 부적절한 인가, 하드코드된 중요정보, 취약한 암호, 난수 |
| 시간 및 상태 | 2 | TOCTOU, 종료되지 않는 반복문 |
| 에러처리 | 3 | 오류 메시지 정보노출, 빈 catch, 광범위 예외 |
| 코드오류 | 5 | Null 역참조, 자원 해제, 역직렬화 |
| 캡슐화 | 4 | **남은 디버그 코드**, 세션 정보 노출 |
| API 오용 | 2 | DNS lookup 의존, 취약한 API |

자료는 소스코드 정적 분석(도구 활용)과 실행 코드 동적 분석(스캐닝, 모의침투)을 모두 소개한다. 항목별 우리 규칙은 `docs/rules/secure-python.md`, `docs/rules/secure-ts.md`에 있다.

참고자료(사전교육 자료 8~12쪽): 소프트웨어 개발보안 가이드, 보안약점 진단가이드, **Python 시큐어코딩 가이드(23년)**, SW 공급망 보안 가이드라인, SW 공급망 보안 강화 로드맵.
