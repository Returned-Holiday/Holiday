# 역할과 일정

## 역할

프론트엔드 2명, 백엔드 2명. 관리자 화면도 프론트엔드가 React로 만든다. 문서 전체에서 아래 역할 코드를 쓴다. 백엔드 세부 분담은 `docs/backend.md`.

| 코드 | 이름 | 역할 |
|---|---|---|
| **FE1** | 수민 | 프론트 리드: 골격, 공통 컴포넌트, 사용자 화면 |
| **FE2** | 현서 | 첫 주 기능명세서·디자인, 이후 관리자 화면과 사용자 화면 일부, 콘텐츠 입력, **AWS 서버 구성·배포** |
| **BE-A** | 유진 | Django 경험. `accounts`, `guides`(설문·체크리스트·OCR), `config`(운영 설정 포함) |
| **BE-B** | 민우 | 보안 강점. `common`(보안 공통), `incidents`, `reports`, `mypage`, CI 보안 도구, **BE-A 코드 보안 검증**, 인프라 검토 |

### 기간별 담당

|---|---|---|---|

| **BE-A** | 백엔드 골격 보완(완료분 확인), **전체 모델·마이그레이션**, ERD 확정 | `accounts`(가입·로그인 잠금·비밀번호 정책·탈퇴·OTP), `guides`(체크리스트 계산·OCR), 조치 관리자 API, 운영 설정(`config/settings/prod.py`·로그 경로)·배포 문서 | 운영 설정 대응, **개발기획서 업데이트**(2·5장은 BE-B와 함께) |
| **BE-B** | `common` 고정 함수 구현, CI 보안 도구, `docs/security.md` 점검 | `incidents`, `reports`, `mypage`와 각 관리자 API, BE-A PR 보안 리뷰, BE-A 기능 보안 테스트 작성 | **진단가이드 기준 전수 점검 주도**, 약점 조치, **서비스 개요서**, **소스코드 최종 정리·제출** |

배치 이유:
- 백엔드는 앱 단위로 통째로 맡는다. 담당 기준은 "코드를 쓰는 사람"이 아니라 "이해하고 설명할 책임이 있는 사람"이다(`docs/backend.md`).
- **BE-B가 BE-A의 보안 테스트를 쓴다.** 만든 사람이 아닌 사람이 테스트를 써야 놓친 부분이 잡힌다.
- **관리자 화면은 FE2가 만들고 그 화면으로 콘텐츠를 직접 입력한다.** 관리자 화면 QA가 자연스럽게 된다.

### 예비안
- BE-A의 2주차(체크리스트 + 운영 설정)가 가장 무겁다. 서버 구성·배포는 FE2. 밀리면 **비밀번호 변경을 3주차 뒤로 미룬다.**
- 일정이 더 밀리면 FAQ는 프론트 정적 페이지로 유지한다(API 없음).
