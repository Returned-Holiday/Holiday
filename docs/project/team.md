# 역할과 일정

## 역할

프론트엔드 2명, 백엔드 2명. 관리자 화면도 프론트엔드가 React로 만든다. 이름은 킥오프에서 채운다. 문서 전체에서 아래 역할 코드를 쓴다.

| 코드 | 이름 | 역할 |
|---|---|---|
| **FE1** | TODO | 프론트 리드: 골격, 공통 컴포넌트, 사용자 화면 |
| **FE2** | TODO | 첫 주 기능명세서·디자인, 이후 관리자 화면과 사용자 화면 일부, 콘텐츠 입력 |
| **BE1** | TODO | 백엔드 리드: 골격, 공통 보안 모듈, 인증·관리자 API, 보안 관련 PR 확인 |
| **BE2** | TODO | 백엔드 도메인: 사고·설문·체크리스트·OCR·제보 API, 인프라 |

### 기간별 담당

| | 10/12–14 설계 | 10/15–23 개발 | 10/24–28 QA·제출물 |
|---|---|---|---|
| **FE1** | Vite 골격(완료), 디자인 토큰, 공통 컴포넌트, API 연결 방식 정리 | 사용자 화면: 메인, 사고 상세, 로그인·가입·비밀번호 변경, 설문, 체크리스트, OCR | 프론트 버그 수정, **시연영상**(10/27) |
| **FE2** | **기능명세서**, 와이어프레임(10/13) → Figma(화면 순서대로) | **관리자 화면**(OTP, 사고·유출 항목, 기업, 조치, 제보 검수), 사용자 화면: 제보, 마이페이지, FAQ, 처리방침. 관리자 화면으로 시드 데이터·가이드 콘텐츠 입력(공식 출처 수집) | **발표자료(ppt + 스크립트)**, 포스터, 기능 QA 주관, 드라이브 제출·디스코드 확인 |
| **BE1** | Django 골격, settings 보안 기본값, CI, **기준 API 1개**, `docs/security.md` | 공통 보안 모듈(권한, 마스킹, 예외, 감사 로그), 회원·인증·잠금·비밀번호 정책·OTP, **관리자 API** | 보안 QA 주관, 약점 조치, **서비스 개요서**, **소스코드 최종 정리·제출** |
| **BE2** | **ERD 확정**, API 명세 | 사고 조회·검색, 설문 → 체크리스트 엔진, OCR(메모리 처리·마스킹·매칭), 제보, AWS 배포(BE1 확인) | 배포 환경 안정화, **개발기획서 업데이트**(2·5장은 BE1과 함께) |

배치 이유:
- **관리자 화면을 FE2가 만들고 그 화면으로 콘텐츠를 직접 입력한다.** 관리자 화면 QA가 자연스럽게 된다.
- **BE1**은 인증·권한·관리자 API처럼 실수가 바로 보안 문제가 되는 부분을 맡는다. 보안 관련 PR은 BE1에게 한 번 보여주고 머지한다(`docs/rules/common.md`).
- **BE2**의 OCR은 업로드가 디스크에 쓰이지 않게 하는 설정이, AWS는 보안그룹·IAM 설정이 핵심이라 BE1이 확인한다.

### 예비안
백엔드 2명의 작업량이 가장 크다(각 약 9인·일). 일정이 밀리면 **FAQ API를 없애고 프론트 정적 페이지로 유지**하고, **제보 화면은 FE2, 제보 API는 BE1이 가져간다.**
