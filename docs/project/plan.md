## 개요

- 트랙: C 공공활용 · 팀명: 반납한연휴 · 프로젝트명: 개인정보 유출 대응 헬프데스크
- 한 줄 소개: 기업·정부기관 공식 발표를 기반으로 유출 항목을 확인하고, 상황 설문과 통지문 OCR로 맞춤 대응 가이드를 제공해 혼란과 스미싱 등 2차 피해를 줄인다.
- 설계 원칙(1-1): 공식 정보 기반(출처 함께 표시) · 상황 맞춤 안내 · 쉬운 행동 안내(무엇을·어디서·어떻게) · 최소 수집·즉시 폐기

## 사용자 유형별 흐름 (1-2)

| 구분 | 이용 범위 | 주요 흐름 |
|---|---|---|
| 비회원 | 사고 조회, FAQ | 검색 → 사고 상세 |
| 회원 | 통지문 캡처, 맞춤 대응 가이드, 제보 | 설문 → 체크리스트 → 진행 저장 |
| 관리자 | 제보 검수, 사고·가이드 관리 | 검수 → 사고 등록 → 공개 |

- 사고 정보 열람은 누구나. 맞춤 대응 가이드와 문자 캡처 인식은 회원 전용(응답·진행 저장, OCR 남용 방지).
- 사고 상세의 "내 대응법 보기" → 로그인 → 상황 설문.
- 캡처로 들어오면 인식된 유출 항목이 설문에 미리 체크된다.
- 찾는 사고가 없으면 회원이 제보 → 관리자 검수.

## 기능 영역 (2-1)

7개 영역: 사고 조회, 맞춤 대응 가이드, 사고 제보, 마이페이지, 계정 관리, 관리자, 보안 공통. 앱 구성은 `docs/backend.md`.

## 사고 조회 (2-2)

- 메인: 기업명 검색, 최근 유출 사고 목록
- 사고 상세에 보여줄 것
    - 유출된 항목 / 유출되지 않은 것으로 발표된 항목(색으로 구분)
    - 발생일, 공지일, 영향 인원(기업 발표 기준)
    - 공지 원문을 바탕으로 한 사고 요약
    - 공식 출처 원문 링크
    - 신고·상담 채널(기업 전담 상담센터, KISA 118 등)
- 유출 대응 상식(FAQ) 페이지

## 맞춤 대응 가이드 (2-3)

1. **문자 캡처 인식**: 이미지는 서버 메모리에서만 처리, 클로바 OCR로 텍스트 추출 → 개인정보 마스킹 → 공식 사고 정보와 대조. 대조된 경우에만 결과 표시. 이미지와 원문은 분석 직후 폐기.
2. **상황 설문**: 3~4문항. 공지된 유출 항목 중 본인 해당 항목, 비밀번호 재사용, 결제수단 연결, 사칭 연락 수신.
3. **맞춤 체크리스트**: 공식 유출 항목과 설문 응답을 조합해 5단계 우선순위로 정렬.
4. **단계별 가이드**: 조치마다 단계별 설명, 공식 출처, 관련 기관 연락처. 유출 항목 유형별로 구성하고 관리자가 사고별로 연결.
5. **진행률 저장**: 체크 즉시 저장, 마이페이지에서 이어서 진행.

| 순위 | 기준 | 설문 응답 | 추가 조치 |
|---|---|---|---|
| 1 | 금전 피해 차단 | 결제수단 연결 | 카드 이용 내역 확인·재발급 |
| 2 | 인증 수단 보호 | 유심 정보 유출 | 유심 보호 서비스 가입 |
| 3 | 진행 중인 공격 대응 | 사칭 연락 수신 | 대응 요령 안내, 118 신고 |
| 4 | 연쇄 피해 예방 | 비밀번호 재사용 | 다른 사이트 비밀번호 변경 |
| 5 | 장기적 도용 예방 | 휴대전화번호 유출 | 명의도용 방지 서비스 확인 |

유출 유형(5대): 이름·연락처, ID·비밀번호, 주민등록번호, 금융정보, 위치정보 (2-3 ④, 활용방안 1-1)

## 사고 제보와 관리자 검수 (2-4)

- 제보 입력: 기업명, 공식 출처 URL(필수, https만), 공지일, 유출 항목
- 제보는 승인 전까지 비공개
- 검수 기준: 출처가 기업·정부기관·언론사의 공식 페이지인지 / 내용이 출처와 일치하는지 / 기존 사고와 중복되지 않는지
- 승인: 공지 원문을 요약해 사고 등록, 대응 가이드 연결, 비공개로 저장해 검토 후 공개
- 반려: 사유 입력, 제보자 마이페이지에 표시

## 시스템·개발 환경 (3, 4장)

- AWS: Route 53 → EC2(nginx TLS 종료 → Gunicorn 127.0.0.1:8000 → Django) → Private Subnet RDS MySQL
- 보안그룹: SG-web(443·80), SG-db(SG-web에서 3306만)
- Secrets Manager(DB 자격증명, OCR 키), CloudWatch Logs, 클로바 OCR
- WAF·ALB·Multi-AZ는 MVP 범위 제외
- FE: React, TypeScript, Vite, React Router, Zustand, styled-components, Axios(CSRF 헤더 자동 첨부)
- BE: Django, DRF, Gunicorn
- 점검 도구: Bandit, Semgrep, pip-audit, npm audit, Dependabot, `check --deploy`
- 인프라 세부는 `infra/README.md`
