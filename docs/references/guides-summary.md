대회 사전교육에서 제시한 문서 3종을 전부 읽고, 우리 서비스에 필요한 내용만 정리했다. 원문은 KISA 지식플랫폼(법령·가이드라인 → 보안취약점 및 침해사고대응)에서 받을 수 있다.

| 문서 | 분량 | 우리에게 쓰이는 곳 |
|---|---|---|
| 소프트웨어 보안약점 진단가이드 (2021, 행안부·KISA) | 612쪽 | **채점 기준 그 자체.** 설계 20개 항목, 구현 49개 약점 |
| 주요정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드 (2026, KISA) | 873쪽 | 진단원이 실제로 해 볼 공격(웹 21개), nginx·DB·클라우드 설정 기준 |
| SW 공급망 보안 강화 로드맵 (2026.6, 관계부처 합동) | 37쪽 | 의존성 관리, SBOM, 취약점 신고 창구 |

## 1. 소프트웨어 보안약점 진단가이드

### 진단 방식
- 설계 단계: 요구사항정의서 → 요구사항추적표 → 아키텍처설계서 → 개발가이드 → 단위·통합 테스트케이스가 이어지는지 확인한다.
- 구현 단계: 도구 + 수동 진단. 1차 진단(파일명·라인·약점·원인·대응) → 제거 → 2차 진단(제거 확인).
- 반복해서 나오는 원칙: **"검증 로직은 공통 모듈로 개발해 일관되게 적용"**, **인가는 화면·기능·데이터 3단계**.

### 설계 20개 항목
SR1-1 DB 조회 / SR1-2 XML / SR1-3 LDAP / SR1-4 시스템 자원 / SR1-5 XSS / SR1-6 CSRF / SR1-7 HTTP 응답·리다이렉트 / SR1-8 메모리 / SR1-9 보안기능 입력값 / SR1-10 업·다운로드 / SR2-1 인증 대상·방식 / SR2-2 인증 수행 제한 / SR2-3 비밀번호 / SR2-4 접근통제 / SR2-5 암호키 관리 / SR2-6 암호연산 / SR2-7 중요정보 저장 / SR2-8 중요정보 전송 / SR3-1 예외처리 / SR4-1 세션통제

우리 적용 방식은 `docs/security.md` 4장.

### 구현 49개에서 Python·TS 관련 판정 예 (정탐 = 약점으로 집계)
- `pickle.loads`로 외부 데이터 역직렬화 → 정탐. HMAC 검증 후 사용은 오탐.
- **MD5는 용도와 상관없이 정탐**(UUID 생성용이어도). SHA1도 취약 알고리즘.
- **보안 결정에 쓰는 일반 난수(Math.random, random 모듈)** → 정탐. `secrets`, `crypto.getRandomValues` 사용.
- `except Exception`(광범위), 빈 except 블록 → 정탐.
- **남은 디버그 코드**(print, console 출력, DEBUG 설정) → 정탐.
- 오류 메시지·스택트레이스 화면 출력 → 정탐. 로그로만 남기면 오탐.
- 설정 파일·properties 값도 외부 입력으로 간주한다.
- 하드코딩된 비밀번호는 해시 형태여도 정탐. 하드코딩 솔트도 정탐.
- 클라이언트 JS에서만 하는 권한 체크 → 정탐.
- CSRF 대책 예시에서 **Django가 명시**되어 있다(개발가이드 1.6.3).

### 부록(산출물 작성 예)에서 쓸 만한 것
- 요구사항 ID 형식(SR-010101), 해결방안·검수기준 칸
- 단위시험 케이스 양식: 시험항목 → 예상결과(예: 개발자도구로 CSRF 토큰 수정 시 저장 안 됨)
- 로그인 실패 테이블(ID, IP, 실패 횟수, 잠금 여부, 시각), 접근 로그(user, 시각, IP, URL, 결과)
- 요청 흐름: Filter → Interceptor → Controller(검증) → View(출력 인코딩). Django로 옮기면 미들웨어 → DRF 인증·권한 → Serializer 검증 → 예외 핸들러 → React 이스케이프

## 2. 주요정보통신기반시설 기술적 취약점 분석·평가 상세가이드

12개 분야 중 우리와 관련된 4개:

| 분야 | 우리 적용 |
|---|---|
| **Web Application 21개(전부 '상')** | 진단원이 해 볼 공격 목록. QA 테스트케이스로 사용 (`docs/security.md` 5장) |
| 웹 서비스 WEB-01~26 | nginx 하드닝 값 (`infra/README.md`) |
| DBMS D-01~26 | DB 계정 최소 권한, 접속 IP 제한, 설정 파일 권한, 감사 로그 |
| 클라우드 CA-01~19 | MFA, Public/Private 서브넷, 공인 IP 최소화, 로깅, 백업, 통신 암호화 |

나머지(Unix·Windows·네트워크·보안장비·제어시스템·PC·이동통신·가상화)는 원칙만 참고: 기본 계정 변경, 세션 타임아웃 10분 내외, 로그인 실패 5회 잠금, NTP, 원격 로그, 패치 관리, 불필요 서비스 제거.

### 웹 21개 항목에서 우리에게 중요한 값
- **IL 개인정보 마스킹 기준**(개인정보위 「홈페이지 개인정보 노출방지 안내서」): 성명 1자 이상(홍\*동), 주민번호 뒤 6자리, 여권번호 뒤 4자리, 연락처 뒤 4자리, 카드번호 7~12번째, 계좌번호 뒤 5자리
- **BF 비밀번호**: 2종 10자 또는 3종 8자, 연속·생일·전화·ID 유사 금지, 반기 1회 이상 변경, 재사용 금지, 실패 3~5회 잠금
- **IS 세션**: 로그인 시 재발급, 타임아웃 10~60분 권고, JWT를 쓴다면 none 알고리즘 거부·짧은 만료
- **IN 권한**: 진단원은 URL의 단순 일련번호부터 변조해 본다. 권한 매트릭스를 만들고 서버에서 일관되게 검사
- **AE 관리자**: 추측 어려운 URL·포트, 지정 IP만, 외부 노출 시 2차 인증
- **WM 메소드**: REST의 PUT/DELETE 자체는 취약하지 않음. 필요 없는 메소드만 막는다
- **SN 전송**: SSLv2/v3 비활성, TLS 1.2 이상

### 로그 보관 근거
- 정보통신망법 제45조, 과기정통부 「정보보호조치에 관한 지침」 별표1 2.2.10: 최소 1개월, 정보보호시스템 3개월
- 이 가이드 밖이지만 적용되는 법령: 「개인정보의 안전성 확보조치 기준」 개인정보처리시스템 접속기록 1년 이상, 월 1회 점검

## 3. SW 공급망 보안 강화 로드맵

- 3전략 9과제: 예방(보안 내재화, SBOM, 보안 개발문화) / 탐지·대응(위협 모니터링, 위험관리, 피해 확산 차단) / 정책·제도(추진체계, 법·제도, 국제협력)
- 공급망 공격 7유형과 사례: 공개SW 취약점(Log4Shell), 타사 의존성, **공용 저장소(PyPI set-utils 타이포스쿼팅, XZ Utils 백도어)**, 빌드 시스템(SolarWinds), 업데이트 가로채기(ASUS), 내부 저장소(Git 기본 계정), 협력사(CCTV 백도어)
- 핵심 개념: **SBOM**(구성 요소 명세), **VEX**(알려진 취약점의 실제 악용 가능성), **CVD**(취약점 신고·조치·공개 절차), NIST SSDF, EU CRA(2027.12 시행)

우리 적용: 의존성 해시 고정, `npm ci`, pip-audit·npm audit·Dependabot, CycloneDX SBOM, CDN 미사용, 패키지 이름 철자 확인(타이포스쿼팅), main 브랜치 보호.

## 4. 가이드 안의 모순·오류 (따라 하면 안 되는 예시)

가이드끼리 값이 다르면 **더 엄격한 쪽**을 고른다.

| 위치 | 내용 | 우리 처리 |
|---|---|---|
| 진단가이드 부록 SR-020603 | 난수 예시가 시간 시드를 쓴 `java.util.Random` | 구현 8번(적절하지 않은 난수)과 모순. `secrets` 사용 |
| 기반시설 WEB-24 | nginx 예시에 `autoindex on` | WEB-04(디렉터리 리스팅 차단)와 모순. off 유지 |
| 기반시설 웹 SI | 예외 처리 예시가 `printStackTrace()` | 진단가이드 기준 오류 메시지 노출 약점 |
| 기반시설 웹 IA | 로그인 예시가 평문 비밀번호 비교 | 해시 비교만 사용 |
| 기반시설 웹 FU | 업로드 실패 시 `ex.Message` 출력 | 일반 메시지만 출력 |
| 기반시설 웹 CF | CSRF 토큰을 `equals`로 비교 | 타이밍 안전 비교(Django 기본 CSRF 사용) |
| 기반시설 D-23 | "비활성화" 예시가 실제로는 값을 1(활성화)로 설정 | 참고만 |
| 기반시설 웹 자동화공격 | 상세 항목 코드가 CC로 표기(목록은 AU, CC는 쿠키변조) | 문서에서는 AU로 표기 |
| 기반시설 HV-13 | 판단 기준 600초, 조치 방법 900초 | 엄격한 값 |
| 사전교육 자료 6쪽·7쪽 | 트랙 표기가 서로 다름(6쪽 C=자유주제, 7쪽 C=공공활용) | 디스코드 확인 대상. 그 밖의 값은 사전교육 자료 기준 |
