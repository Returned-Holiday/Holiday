# 기능명세서

담당: 프론트(FE1). 화면별 기능·흐름·빈 상태·에러 상태는 구현된 화면 기준(10/22)이고, **보안 동작** 칸은 `docs/security.md` 기준이다. 화면을 바꾸면 이 문서를 같은 PR에서 고친다.

화면별로 아래 양식을 쓴다. 관리자 화면도 React로 만들며 맨 아래에 정리했다.

```
### 화면 이름 (경로)
- 대상: 비회원 / 회원
- 목적:
- 기능:
- 입력 필드: 이름, 형식, 길이, 필수 여부
- 정상 흐름:
- 빈 상태:
- 에러 상태:
- 사용 API:
- 보안 동작:
```

공통 규칙:
- 로딩 중에는 "불러오는 중이에요" 류의 문구를 `role="status"`로, 실패하면 일반 문구와 "다시 시도" 버튼을 `role="alert"`로 보여 준다. 서버 에러 원문은 보여 주지 않는다.
- 입력 검증 에러는 서버가 준 칸별 문구(`fields`)를 해당 칸 아래에 보여 준다. 칸이 없는 에러는 일반 문구만 보여 준다.
- 요청 제한(429)은 화면마다 "잠시 후 다시 시도" 안내를 보여 준다.

## 공개 화면 (비회원 포함)

### 메인 (`/`)
- 대상: 전체
- 목적: 기업명 검색, 최근 공지된 사고 목록
- 최근 사고 목록은 공지일 최신순 하나만 둔다. 대응 인원 순위 목록은 두지 않는다(10/13 결정)
- 기능:
  - 검색창(기업 이름, 50자) → 사고 검색 결과로 이동
  - 최근 공지 사고 4건 목록, 검색 영역에 최근 3건 바로가기
  - 로그인 카드: 비로그인이면 로그인 폼, 로그인 상태면 "○○ 님, 반가워요" + "내 대응 이어서 하기"(마이페이지)·"문자로 사고 찾기"(OCR)
  - 빠른 메뉴: 사고 조회, 문자로 찾기, 맞춤 체크리스트, 유출 대응 상식, 사고 제보
  - KISA 118 안내, 유출 대응 상식 주요 질문
- 빈 상태: "아직 공개된 사고가 없어요."
- 에러 상태: 최근 목록 영역에 "목록을 불러오지 못했어요." + 다시 시도
- 사용 API: `GET /api/incidents/`
- 보안 동작:
  - 검색어 최대 50자
  - 공개된 사고만 보임

### 사고 상세 (`/incidents/:id`)
- 대상: 전체
- 목적: 기업 발표 기준 유출·미유출 항목, 발생·공지일, 영향 인원, 요약, 공식 출처, 상담 채널
- 제목 위 대응 상태 배지: "대응 진행 중" / "대응 종료". 관리자가 지정한 값(`responseStatus`) 그대로 표시
- 기능:
  - 유출된 항목(칩), 어려운 용어 풀이, 유출되지 않은 것으로 발표된 항목(있을 때만)
  - 사고 요약, 공식 출처 원문 링크(새 창, 도메인 표시)
  - "개인별 맞춤 대응 진단 받기"(설문으로), 기업 상담 채널과 KISA 118
- 정상 흐름: 상세 확인 → "내 대응법 보기" → (비로그인이면 로그인 후 돌아와) 상황 설문
- 빈 상태: 유출 항목이 없으면 "발표된 유출 항목이 아직 없어요."
- 에러 상태: 불러오기 실패 "사고 정보를 불러오지 못했어요." + 다시 시도. 숫자가 아닌 ID·비공개·없는 사고는 404 화면
- 사용 API: `GET /api/incidents/<id>/`
- 보안 동작:
  - 비공개·없는 사고는 404 화면(어느 쪽인지 구분하지 않음)
  - 출처 링크는 새 창 + 도메인 표시(`SafeExternalLink`)
  - "내 대응법 보기"는 비로그인 시 로그인으로 이동 후 복귀

### 유출 대응 상식 FAQ (`/faq`)
- 프론트 정적 콘텐츠. 공통 기관 연락처(KISA 118 등) 포함
- 내용: 분류 5개(잘못 알려진 대응법, 유출 확인 방법, 사칭·스미싱 구별, 신고·상담 기관, 용어 풀이). 질문마다 공식 출처 링크
- 기능: 왼쪽 분류 선택, 질문 펼치기·접기. 주소의 `#` 값으로 특정 분류·질문을 바로 열 수 있음(메인 주요 질문에서 이동)
- 보안 동작: 외부 링크는 `SafeExternalLink`

### 개인정보 처리방침 (`/privacy`)
- 모든 화면 하단에서 접근
- 내용: 처리 항목과 목적(자동 수집 항목 포함), 보유 기간과 파기, 처리 위탁(네이버 클라우드 CLOVA OCR, AWS), 국외 이전(AWS 시드니 리전, 호주), 제3자 제공, 안전성 확보 조치, 이용자 권리, 쿠키, 보호책임자, 권익침해 구제 방법, 방침 변경
- 문구: `Front/src/features/policy/privacy.ts`. 남은 일: 개인정보 보호책임자 성명·연락처(팀 결정 필요)

### 이용약관 (`/terms`)
- 모든 화면 하단과 회원가입 동의에서 접근
- 문구: `Front/src/features/policy/terms.ts`. 주요 조항(목적, 서비스, 책임의 한계)은 펼쳐서, 나머지는 접어서 보여 준다

### 사고 검색 결과 (`/incidents?q=`)
- 대상: 전체
- 목적: 메인 검색·"사고 조회" 메뉴의 결과. 사고 카드(대응 상태, 기업명, 대표 유출 항목, 공지일)
- 기능: 검색어 없으면 최근 공지된 사고 전체. 20건씩 이전·다음 페이지
- 빈 상태: "'검색어'에 해당하는 공개된 사고가 없어요" + 제보 안내
- 에러 상태: "검색 결과를 불러오지 못했어요." + 다시 시도. 없는 페이지 번호(`?page=999`)는 첫 페이지로 이동
- 사용 API: `GET /api/incidents/?q=&page=`
- 보안 동작: 검색어 50자, 공개된 사고만

### 오류 화면
- 404, 500, 네트워크 오류 공통 화면
- 404 문구는 "주소가 바뀌었거나 없는 페이지예요" 하나(비공개 사고·관리자 화면 존재 비노출)
- 500·화면 오류: "잠시 문제가 생겼어요" + 다시 시도 + KISA 118 안내
- 보안 동작: 내부 정보(에러 원문, 경로, 버전) 없음

## 인증 화면

### 회원가입 (`/signup`)
- 입력:
  - 이메일(형식 검사, 최대 254자, 필수)
  - 비밀번호(최대 64자, 필수), 비밀번호 확인(일치하면 "비밀번호가 일치해요")
  - 닉네임(한글·영문·숫자 2~20자, 필수)
  - 동의 3개(이용약관, 개인정보 수집·이용, 만 14세 이상) + 전체 동의. 약관·처리방침은 새 창으로 보기
- 정상 흐름: 칸을 벗어날 때마다 검사 → 가입하기 → 로그인 화면에 "가입이 끝났어요. 로그인해 주세요." 자동 로그인 없음
- 에러 상태: 칸별 서버 문구(이메일·비밀번호·닉네임·동의), 이미 가입된 이메일(409), 요청 제한(429)
- 로그인 상태로 들어오면 메인으로 이동
- 사용 API: `POST /api/auth/signup/`
- 보안 동작:
  - 비밀번호 규칙을 입력 중에 안내: 2종 10자 또는 3종 8자, 연속·반복 문자 금지, 이메일 아이디 포함 금지
  - 서버도 같은 규칙으로 다시 검증
  - 수집 항목 안내 + 처리방침 링크
  - 전송 후 비밀번호는 화면 상태에서 지움

### 로그인 (`/login`)
- 입력: 이메일, 비밀번호
- 정상 흐름: 로그인 → 원래 보던 화면(같은 출처 경로만) 또는 메인. 비밀번호 90일 경과면 비밀번호 변경 화면
- 에러 상태: 빈 칸 "이메일과 비밀번호를 입력해 주세요.", 실패·잠금은 서버 문구 그대로
- 사용 API: `POST /api/auth/login/`, `GET /api/auth/me/`
- 보안 동작:
  - 실패 문구는 하나: "이메일 또는 비밀번호가 일치하지 않습니다"
  - 5회 실패 시 "30분 후 다시 시도해 주세요"
  - 비밀번호 90일 경과 시 비밀번호 변경 화면으로 이동
  - **비밀번호 찾기 기능 없음.** 안내 문구: "비밀번호 찾기는 제공하지 않아요. 비밀번호를 잊었다면 다른 이메일로 새로 가입해 주세요."
  - 로그인 후 돌아갈 경로는 같은 출처 경로만(오픈 리다이렉트 차단)

### 비밀번호 변경 (`/account/password`)
- 입력: 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인
- 정상 흐름: 강제 변경(90일 경과)이면 변경 후 메인, 직접 들어온 경우 마이페이지에 "비밀번호를 바꿨어요."
- 에러 상태: 칸별 서버 문구(현재 비밀번호 불일치, 규칙 위반, 최근 4개 재사용, 하루 이내 재변경), 요청 제한(429)
- 사용 API: `POST /api/auth/password/`
- 보안 동작:
  - 90일 경과로 들어온 경우 다른 메뉴로 이동 불가(서버도 다른 API를 403으로 막음)
  - 최근 4개와 같은 비밀번호, 변경 후 1일 이내 재변경 거부(강제 변경은 예외)
  - 변경 후 "다른 기기에서는 로그아웃됩니다" 안내

### 세션 만료
- 마지막 서버 응답 후 15분이 지나면 화면을 만료 처리하고 "오랫동안 움직임이 없어서 로그아웃됐어요" 창을 띄운다. "다시 로그인" → 로그인 후 원래 화면으로 복귀
- 다른 요청이 401을 받아도 같은 창을 띄운다. 여러 탭을 열어 두면 마지막 응답 시각을 탭끼리 공유한다
- 만료 확인용으로 서버를 호출하지 않는다(호출 자체가 세션을 연장하므로)

## 회원 화면

### 통지문 캡처 인식 (`/ocr`)
- 목적: 유출 안내 문자·메일 캡처로 사고와 유출 항목 찾기
- 기능: 끌어다 놓기 또는 "이미지 선택", 업로드 전 안내(저장 안 함, CLOVA OCR 전송, 개인정보는 가린 뒤 매칭)
- 정상 흐름: 이미지 선택 → "문자를 읽고 있어요" → "○○ 개인정보 유출 사고와 일치해요" + 찾은 항목 → "설문 시작하기"(찾은 항목이 1번에 미리 체크됨)
- 빈 상태: 일치하는 사고가 없으면 "등록된 공식 사고와 일치하지 않아요" + 다른 이미지 올리기, 기업 이름으로 검색하기 링크
- 에러 상태: 형식 "JPG·PNG 이미지만 올릴 수 있어요.", 크기 "5MB 이하 이미지만 올릴 수 있어요.", 요청 제한 "1시간에 10번까지 올릴 수 있어요…", 외부 OCR 실패 "지금은 이미지를 인식할 수 없어요…"
- 사용 API: `POST /api/guides/ocr/`
- 보안 동작:
  - **업로드 전에** 외부 처리 위탁(네이버 클라우드 CLOVA OCR) 고지
  - JPG·PNG, 최대 5MB 안내(검사는 사용성용, 실제 검증은 서버)
  - 등록된 사고와 일치할 때만 결과 표시. 인식한 원문은 보여주지 않음
  - "이미지는 저장되지 않고 분석 직후 삭제됩니다" 안내
  - 요청 제한(시간당 10회) 초과 시 안내

### 상황 설문 (`/incidents/:id/survey`)
- 문항 (임시, 설문 명세 작성 중). `{기업명}`은 자동 삽입
    1. 공지된 유출 항목 중 나에게 해당하는 것을 모두 골라 주세요 — 항목 복수 선택(그 사고의 "유출" 항목만) / 잘 모르겠어요 / 해당하는 항목이 없어요 중 하나
    2. {기업명}에 카드나 계좌 같은 결제수단을 등록한 적이 있나요? — 예 / 아니요 / 잘 모르겠어요
    3. {기업명}에서 쓰던 비밀번호를 다른 사이트에서도 쓰고 있나요? — 예 / 아니요 / 잘 모르겠어요
    4. 사고 이후 {기업명}이나 기관을 사칭한 문자·전화·메일을 받은 적이 있나요? — 예 / 아니요 / 잘 모르겠어요
    5. 사고 이후 모르는 결제나 로그인 알림처럼 이상한 일을 겪었나요? — 예 / 아니요 / 잘 모르겠어요
- 모든 문항 필수. 1번도 세 가지 중 하나를 반드시 고른다
- 설문 위: 진행 단계(1/5), 이 사고의 유출 항목 목록, "지금 N명이 대응 중"
- OCR에서 들어온 경우 인식된 항목이 1번에 미리 체크됨(해제 가능)
- 다시 하는 경우 이전 답이 채워져 있음. 그 사이 미유출로 바뀐 항목은 빠짐
- 정상 흐름: 한 문항씩 "다음" → 마지막 "내 할 일 목록 보기" → 저장 후 체크리스트. 1번에서 "이전"은 사고 상세로
- 에러 상태: 답하지 않고 다음 "답을 하나 골라 주세요.", 불러오기 실패 "설문을 불러오지 못했어요…", 저장 실패는 서버 문구(저장 중 공지가 바뀌면 새로고침 안내). 비공개·없는 사고는 404 화면
- 사용 API: `GET·PUT /api/guides/incidents/<id>/survey/`, `GET /api/incidents/<id>/`
- 하단 안내: "답변은 할 일 목록을 만드는 데만 쓰이고, 마이페이지에서 언제든 지울 수 있어요"
- 보안 동작:
  - 선택지는 서버가 준 "유출" 항목만
  - 답으로 개인정보를 받지 않음(카드 번호, 받은 문자 내용 등은 묻지 않음)

### 맞춤 체크리스트 (`/incidents/:id/checklist`)
- 맨 위 기본 안내: 사고의 공지 원문 링크, 기업 상담 채널(진행률 제외)
- 우선순위 1~5 순 조치 목록, 단계별 설명, 출처, 기관 연락처, 진행률
- 1~3순위는 "지금 바로 하세요"(긴급), 4~5순위는 "여유가 될 때 하세요"(권장)로 묶고, 아직 안 한 첫 긴급 조치의 단계별 방법을 펼쳐 둔다
- 조치마다 걸린 이유(`reason`: "유출 항목: 연락처", "설문: 결제수단 연결", "이 사고 안내")
- (임시) 같은 순위 안에서 확실 → 확인 필요 순. 확인 필요 조치에 "해당되는지 먼저 확인하세요" 표시
- (임시) 1번 "잘 모르겠어요"면 상단에 "해당 항목을 고르지 않아 공지된 모든 항목 기준으로 보여드려요"
- 걸린 조치가 없으면 "선택한 내용으로는 추가 조치가 없어요" + 기본 안내 + 설문 다시 하기·사고 상세로
- "새 조치" 표시, "공지 내용이 갱신됐어요. 설문을 다시 확인해 주세요" 배너(설문 다시 보기)
- 정상 흐름: 조치 체크 → 바로 저장 → 진행률·목록을 서버 값으로 다시 받음. 모두 끝나면 "모든 조치를 마쳤어요!"
- 에러 상태: 불러오기 실패 "할 일 목록을 불러오지 못했어요." + 다시 시도, 체크 저장 실패 "체크를 저장하지 못했어요. 다시 시도해 주세요." 설문 응답이 없으면(404) 설문 화면으로 이동
- 사용 API: `GET /api/guides/incidents/<id>/checklist/`, `PUT·DELETE /api/guides/incidents/<id>/completions/<action_id>/`
- 보안 동작: 목록·우선순위·진행률은 서버 계산값만 표시

### 사고 제보 (`/reports/new`)
- 입력: 기업명(최대 100자, 필수), 공식 출처 URL(https, 최대 500자, 필수), 공지일(날짜, 선택), 유출 항목(자유 텍스트, 최대 1,000자, 필수, 글자 수 표시)
- 정상 흐름: 제보하기 → "제보가 접수됐어요" + "제보 내역 보기"(마이페이지)
- 에러 상태: 칸별 검사 문구, 서버 칸별 문구, 요청 제한 "제보는 하루에 5번까지 할 수 있어요…"
- 사용 API: `POST /api/reports/`
- 보안 동작:
  - "개인정보를 입력하지 마세요" 안내, 글자 수 표시
  - https가 아닌 URL은 입력 단계에서 거부(서버도 검증)
  - 저장 시 개인정보 패턴은 마스킹된다는 안내

### 마이페이지 (`/me`)
- 내 대응 중 사고와 진행률, 내 제보 목록(상태·반려 사유), 계정 정보
- 기능:
  - 사고 카드(공지일 최신순): 진행률, 남은 긴급 조치 수와 다음 긴급 조치, "이어서 하기"(체크리스트)
  - 제보 내역: 검수 대기·승인됨·반려됨, 반려면 "반려 사유 보기"
  - 계정: 닉네임·이메일, 비밀번호 마지막 변경일(며칠 전), 비밀번호 변경, 회원 탈퇴
- 사고 카드마다 "대응 기록 삭제": 확인 창에서 삭제되는 것(설문 응답, 완료 기록) 안내 → 확정. 비밀번호는 묻지 않음
- 빈 상태: "아직 대응 중인 사고가 없어요." + 내 사고 찾기, "아직 제보한 사고가 없어요."
- 에러 상태: "정보를 불러오지 못했어요." + 다시 시도. 삭제·탈퇴 실패는 서버 문구(탈퇴는 현재 비밀번호 칸 아래)
- 정상 흐름(탈퇴): 탈퇴하기 → 삭제 목록 확인 → 현재 비밀번호 → 탈퇴 후 메인(로그아웃 상태)
- 사용 API: `GET /api/mypage/`, `GET /api/reports/`, `GET /api/auth/me/`, `POST /api/auth/withdraw/`, `DELETE /api/guides/incidents/<id>/survey/`
- 보안 동작:
  - **비밀번호 마지막 변경일** 표시. 마지막 로그인 시각은 표시하지 않음(10/13 결정)
  - 대응 기록 삭제는 본인 기록만(서버가 `request.user`로 삭제)
  - 반려 사유는 텍스트로만 표시
  - 탈퇴: 삭제되는 데이터 목록 안내 → 현재 비밀번호 입력 → 확정

### 공통
- 모든 화면 같은 위치(헤더)에 로그아웃 버튼
- 비밀번호 만료 상태면 헤더 메뉴를 숨기고 비밀번호 변경 화면(처리방침·약관 제외)으로만 이동
- 로딩 상태, 키보드 탐색, 시맨틱 HTML·ARIA(기획서 4-2). 본문 바로가기 링크

## 관리자 화면 (`/manage`)

공통 보안 동작:
- 관리자가 아니면 404 화면을 보여 준다(관리자 화면이 있다는 사실을 드러내지 않음)
- 관리자 화면 코드는 별도 파일로 나눠 관리자만 내려받는다
- 로그인 후 OTP 6자리를 입력해야 관리자 화면을 쓸 수 있다
- 일반 화면에 관리자 메뉴·링크가 없다
- 입력값은 텍스트로만 표시(사용자 제보 내용 포함)
- 실제 보호는 서버(허용 IP, `is_staff`, OTP)가 맡는다

공통 화면 동작:
- 목록은 끝까지 불러온다. 1,000건을 넘으면 "목록이 많아 앞의 1,000건만 보여요" 안내
- 저장 실패는 서버의 칸별 문구를 보여 준다

### 관리자 OTP 인증 (`/manage/otp`)
- 입력: OTP 6자리(칸 6개, 붙여넣기 가능)
- 정상 흐름: 확인 → 사고 관리 화면. 이미 인증했으면 바로 사고 관리로
- 에러 상태: 6자리 미입력 "6자리 숫자를 모두 입력해 주세요.", 실패는 원인 구분 없이 "인증 번호를 확인하지 못했어요. 인증 앱의 새 번호로 다시 입력해 주세요."(입력칸 비움)
- 사용 API: `POST /api/auth/otp/`
- 보안 동작: 5회/분 제한, 실패 문구 하나로 통일

### 사고 관리 (`/manage/incidents`, `/manage/incidents/:incidentId`)
- 목록(공개·비공개 모두), 등록, 수정, 유출 항목 추가·수정·삭제, 공개 전환, 대응 상태(진행 중 / 종료) 변경
- 목록: 사고명·기업명 검색, 전체·공개·비공개 필터. 빈 상태 "조건에 맞는 사고가 없어요."
- 등록·수정 입력: 기업(기업 관리에 등록된 기업 중 선택, 필수), 발생일, 공지일(필수), 영향 인원(숫자), 공식 출처 URL(https, 필수), 기업 상담 채널(500자), 요약(2,000자, 필수), 대응 상태
- 저장 버튼: 비공개 사고는 "비공개로 저장"·"검토 완료 · 공개하기", 공개 사고는 "비공개로 내리기"·"저장". Enter로 제출하면 지금 공개 상태를 유지
- 유출 항목 추가: 발표 원문 표현, 유출 / 미유출, 유출 유형(필수). 사고를 먼저 저장해야 추가 가능
- 공통 조치는 유출 항목의 유형으로 자동 연결된다. 사고 화면에서 조치를 고르지 않는다. 이 사고만의 특수 조치는 조치 관리에서 추가
- 에러 상태: 입력 검사 문구, 사용자가 고른 항목 삭제(409) "사용자가 이미 고른 항목은 지울 수 없어요. 수정으로 정정해 주세요."
- 사용 API: `/api/admin/incidents/`, `/api/admin/incidents/<id>/leak-items/`
- 보안 동작:
  - 신규 등록은 비공개
  - 출처는 https만
  - 사용자가 고른 유출 항목은 삭제 불가 안내(수정으로 정정)
  - 유출 항목을 바꾸면 사용자에게 "공지 갱신" 배너가 뜬다는 안내

### 기업 관리 (`/manage/companies`)
- 기업명(100자), 별칭(검색·OCR 매칭용, 기업당 20개, 각 50자). 입력 후 Enter로 별칭 추가
- 빈 상태: "등록된 기업이 없어요."
- 에러 상태: 다른 기업의 이름·별칭과 겹치면 "다른 기업(○○)에 이미 있는 이름이라 별칭으로 쓸 수 없어요"(띄어쓰기·대소문자·전각 문자 무시), 개수·길이 초과 안내, 서버 중복(409)
- 사용 API: `/api/admin/incidents/companies/`
- 보안 동작: 다른 기업과 같은 별칭은 저장 불가
- 흐름: 왼쪽 목록에서 고르거나 "+ 기업 추가" → 저장

### 조치 관리 (`/manage/actions`)
- 공통·특수 조치, 트리거(유형·설문·항상), 우선순위 1~5, 단계별 설명(한 줄에 한 단계), 출처, 공개 전환
- 목록은 우선순위 순, 공개 여부와 트리거 요약 표시. 빈 상태 "등록된 조치가 없어요."
- 버튼: "저장"(지금 공개 상태 유지), 비공개 조치는 "공개하기", 공개 조치는 "비공개로 내리기"
- 에러 상태: 트리거별 필수값 문구, 완료한 사용자가 있는 조치의 대상 사고·트리거 변경(409) "새 조치를 등록하고 이 조치는 비공개로 내려 주세요" 안내
- 사용 API: `/api/admin/guides/actions/`
- 보안 동작: 삭제 없음(비공개로 내림), 트리거별 필수값 검증

### 제보 검수 (`/manage/reports`)
- 대기·승인·반려 목록(탭에 건수), 상세, 승인(반영 사고 연결) / 반려(사유 필수)
- 승인: 검수 체크 3개(공식 출처, 내용 일치, 중복 아님)를 모두 체크해야 가능. 반영 방법은 "새 사고로 등록"(승인 후 사고 관리에서 작성) 또는 "이미 있는 사고에 연결"
- 빈 상태: "해당하는 제보가 없어요.", 고르기 전 "왼쪽에서 제보를 골라 주세요."
- 에러 상태: 반려 사유 없음 "반려 사유를 입력해 주세요.", 없는 사고 연결(400) 서버 문구, 다른 관리자가 먼저 검수(409)면 상세를 다시 불러와 검수 결과를 보여 줌
- 사용 API: `/api/admin/reports/`
- 보안 동작: 제보 내용은 저장 시 마스킹된 값만 표시, 검수자·시각 자동 기록
